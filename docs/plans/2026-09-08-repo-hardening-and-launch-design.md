# Repo Hardening & Launch — Design

**Date:** 2026-09-08
**Status:** Approved (decisions confirmed by Milos on 2026-09-08; open questions listed at the end)
**Scope:** the `portfolio` monorepo plus the machine-level Claude Code workflow layer that governs how work on it is done

## 1. Context

A full workspace review on 2026-09-08 found:

- **The site is not live.** `miloscvetkovic.dev` and `www.` resolve to a Namecheap parking page. No Vercel project, no GitHub deployments, no CI. The "Go live" PR (#2, 2026-02-23) was a code merge, not a launch.
- **Five months of uncommitted work** (2026-03-29): 59 files were a pure Prettier reformat with _default_ options because the shared `@repo/prettier-config` is not referenced by any workspace; 4 files carried real changes (pnpm 9→10 bump, a Featured Work redesign with an interactive architecture diagram, two small perf tweaks).
- **Quality gates were red or missing.** `pnpm lint` fails (7 React Hooks v7 errors on `main`, 3 more in the WIP). 3 of 9 Playwright tests fail on a clean `main`. `pnpm typecheck`, `lint:fix` and `clean` have no Turbo task. Husky is installed but has no hook scripts and there is no commitlint config, so the documented commit discipline was never enforced.
- **Housekeeping debt:** two merged worktrees (1.5 GB), stale branches, `.claude/worktrees` not ignored, dependencies 6+ months behind.

## 2. Goals

1. Every documented command works and every gate is green: format, lint (0 warnings), typecheck, unit, build, e2e.
2. The gates run automatically: pre-commit, commit-msg, and GitHub Actions on every push and PR.
3. The Featured Work redesign is finished, tested, accessible, and shipped.
4. The repository reads as a reference-quality engineering setup: README, ADRs, runbooks, plans with tracked progress.
5. The site is deployed on Vercel behind `miloscvetkovic.dev`.
6. The machine-level Claude Code workflow (Addy Osmani's agent-skills, the loop-engineering discipline from `claude-code-monorepo`) is installed once and documented, so every project on this machine follows it.

**Non-goals (deliberately deferred):** major dependency upgrades (Next 16.3, Tailwind 4.3, Vitest 5, ESLint 10, TypeScript 7), blog content, contact form, analytics, Lighthouse budgets. Dependabot will surface upgrades as separate PRs.

## 5. Workflow layer (machine level, `~/.claude`)

| Piece                                                                     | Location                                                                                                   | Mechanism                                                                                                                                                                                                                 |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Addy Osmani agent-skills (25 skills, 9 commands, 4 personas)              | `~/.claude/.cache/addy-agent-skills` (git clone) → symlinks/copies in `~/.claude/{skills,commands,agents}` | `~/.claude/scripts/sync-agent-skills.sh` (idempotent; pulls and relinks)                                                                                                                                                  |

| Safety                                                                    | `~/.claude/settings.json`                                                                                  | deny reads of `~/.ssh`, `~/.aws`, `~/.azure`, `*.pem`, `*.key`, `id_rsa`; `GIT_EDITOR=true`, `GIT_TERMINAL_PROMPT=0`, `GIT_MERGE_AUTOEDIT=no`                                                                             |
| Doctrine                                                                  | `~/.claude/CLAUDE.md` § Development workflow                                                               | maker ≠ checker; verifiable stop conditions; lifecycle `/spec → /plan → /build → /test → /review → /ship`; skill precedence; documentation and progress-tracking conventions                                              |

Skill precedence on this machine (adapted from the book): **1.** project skills and CLAUDE.md, **2.** Addy agent-skills for engineering process (build, test, review, debug, ship), **3.** BMAD personas for product-level work that needs PM → Architect → Dev hand-offs, **4.** superpowers for meta-workflows only (brainstorm, write-plan, execute-plan, worktrees).

## 6. Verification

- Every PR's stop condition above is a command, not an opinion.
- Maker ≠ checker: before a PR is declared ready, a separate agent (`adversarial-reviewer` on the diff only, `edge-case-hunter` on changed files, `ui-reviewer` for components) reviews it and findings are triaged in the PR description.
- Progress is tracked as checkboxes in the plan documents and updated in the same commit as the work.

## 7. Open questions (answers change nothing already built)

1. **Merge policy.** Should Claude squash-merge PRs itself once CI is green, or leave every merge to Milos? Default until answered: open the PR and wait.
2. **Branch protection on `main`** (require the `quality` and `e2e` checks, no force-push). Recommended; needs an explicit go-ahead because it is a persistent repository setting.
3. **Shared `@repo/eslint-config` and `@repo/typescript-config`** are not referenced by any app either. Wire them (risk: duplicate plugin registration with `eslint-config-next`) or delete them? Default: leave for a follow-up PR.
4. **License** for the repository (code MIT, content reserved?). Legal choice; default: none added.
5. **PM ceremony** (`/pm:*` from the book) for future epics on this machine? Default: documented, not installed.

## 8. Assumptions

1. `main` is the deployable branch and the only long-lived branch.
2. Vercel free tier is acceptable; no other hosting is in play.
3. The three case-study metrics (73.4 %, 99.98 %, 5.2×) are accurate claims Milos stands behind; the UI must not distort them.
4. Node 22 stays the runtime for the next few months (Node 24 LTS is available; switching is a one-line change to `.nvmrc`).
5. No secrets are needed to build or run the site.
