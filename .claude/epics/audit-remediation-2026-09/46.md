# Task: Fix the mobile navigation and phone-width layout

## Description

On a phone the navigation is broken on every route. The mobile menu opens as a transparent strip clipped to the 72px header: its six links are drawn straight over the page with no panel behind them, and a tap outside cannot close it, because the header's `backdrop-blur-sm` makes the header the containing block for the menu's `fixed` layers. The same menu has no dialog semantics, no Escape handling and no focus management, so a keyboard or screen-reader user is never told it opened, cannot dismiss it and loses their place when it closes. On the home page the story's Execution grid (and, at 320px, the Strategy grid) sizes its single column to the code sample instead of to the viewport, so the whole page pans sideways by 49 to 143px at 320 to 414px once the story has settled, with the build stats, the elapsed timer and the right end of the code off-screen. A GSAP from-state adds another 30px on phones and makes tablets and desktop windows between 768 and 1083px scroll sideways until the Execution reveal plays. Most first visits to a portfolio arrive on a phone, and no gate sees any of this: the suite runs one desktop project until #43 adds phone projects. This task also clears the low-severity navigation and page polish found alongside, so one PR covers the whole phone and keyboard path through the site.

Branch: fix/mobile-nav-and-overflow. Lands as one PR, squash-merged.

- **Key considerations and traps.**
  - Tailwind v4's preflight zeroes `margin`, `padding` and `border` on every element and on `::backdrop`, which removes the user-agent `margin: auto` from `dialog:modal`. The user-agent sheet still applies `max-width`/`max-height` of `calc(100% - 6px - 2em)`, `background-color: Canvas` and `color: CanvasText`. Set the panel geometry on the dialog (right-aligned, full dynamic viewport height, `max-h`/`max-w` cleared) and set both `bg-[var(--background)]` and `text-[var(--foreground)]` on it: the dark theme declares no `color-scheme` yet (that is #48), so `CanvasText` resolves to black and the Close icon, drawn with `currentColor`, would disappear on the dark panel.
  - Keep the backdrop a literal colour, `backdrop:bg-black/50`, matching today's overlay (`navigation.tsx:77`). Custom properties do not reach `::backdrop` in every engine.
  - Put no display utility (`flex`, `grid`, `block`) on the `<dialog>` itself: author CSS beats the user-agent `dialog:not([open]) { display: none }`, so a closed dialog carrying `flex` renders in the page flow. Lay the panel out on the inner wrapper, or use the `open:` variant.
  - jsdom 30.0.1, the version the lockfile resolves, implements no dialog behaviour at all: `HTMLDialogElement-impl.js` is an empty subclass of `HTMLElement`, with no `show`, `showModal` or `close`. The dialog's behaviour is therefore proven in Playwright, and any Vitest file that renders `Navigation` stubs `HTMLDialogElement.prototype.showModal`/`close` and `matchMedia` in its own `beforeEach` (CLAUDE.md, Testing: stubs are per file, not global).
  - e2e specs wait for hydration before tapping, because events fired earlier are lost; on `/` that is the `System Boot` loader being hidden. Compare `scrollWidth` with `document.documentElement.clientWidth`, never with `innerWidth`: under phone emulation the layout viewport widens to the content (463 against a `clientWidth` of 390 on iPhone 13).
  - An absence check can pass for the wrong reason. A "no overflow" read taken right after hydration can land before GSAP applies a from-state, which is why AC 9 samples across a 2 s window with motion allowed, and why the reduced-motion rows cannot cover hero-v1.
  - Keep the overflow work cheap — one load per width and one story walk — so the e2e job stays inside its 20-minute timeout with the phone projects added (PRD, Non-Functional Requirements). The gate specs keep `retries: 0`; do not relax them to quieten a run.

### Architecture Patterns

- N/A — no architecture document for this epic. Standing decisions that apply:
  - ADR 0006, Hydration-safe client state: the menu's open state starts `false` on server and client and changes only in event handlers; no browser state is read during render, and no Hooks rule is silenced.
  - ADR 0009, Animation performance rules for the home page: rule 4 keeps the six story sections in the document from the first paint, which is why the overflow is measurable at rest; rule 5 keeps `app/layout.tsx` importing `Navigation` from its own module rather than the barrel; rule 2 keeps repeating animations on `transform` and `opacity`, which the reworked stats from-state respects.
  - ADR 0010, Status colour tokens: the tech-tree cards' `--status-ok` marks keep their tokens and their full opacity at rest while the card layout changes.
  - ADR 0011, Colour roles, corrected for scoped surfaces and stacked tints (superseding 0008): `--accent-text` for the current link's text, `--accent` for surfaces, and the dialog panel sets `color` on the same element that carries its background.
  - ADR 0014, Playwright starts the server it tests, on a port of its own: port 3210 by default, `PLAYWRIGHT_PORT` to move it.
  - ADR 0015, Case-study slugs are fixed at build time: the per-route overflow checks read the slugs from `case-studies.ts`.
  - From the epic's Architecture Decisions: the mobile menu is a native `<dialog>` opened with `showModal()`; colours come only from the theme tokens, with no alpha on text; RED-first tests, with the gate specs at `retries: 0`; static prerendering stays; one or more small PRs from a typed branch, squash-merged.
