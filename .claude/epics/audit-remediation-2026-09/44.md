# Task: Get production back to main and keep deploys within the Vercel quota

## Description

Merging to `main` has stopped meaning "shipped". On 2026-09-10 preview builds - a third of them from
Dependabot branches - used up the Hobby plan's 100 deployments for the day, and the production builds of the
last two merges were refused with "Deployment rate limited - retry in 24 hours". Vercel never retried, so
production has served 6e0a87a since 15:52Z that day while `main` is at 9189af4, and the keyboard and
screen-reader fix for the story dots is merged but not live. Nothing alerted on the lag: the project sends no
analytics, no error monitoring and no uptime signal, which is why it went unnoticed for over a day. The
runbook's recovery step makes it worse, because `vercel redeploy` rebuilds the commit that is already
deployed and cannot catch production up. This task deploys `main`, stops the quota being spent on builds
nobody reads, and makes the runbook true where an operator would reach for it under pressure - including two
instructions that point at a page that was deleted and a command a standing decision rejected. Branch:
ci/vercel-ignored-build-step. Lands as one PR, squash-merged.

## Technical Details

**Order of work.** Catch production up first, before any repository change: the lag is the live defect and it
needs no code. The 24-hour window has long passed and Vercel has not retried, so a deployment has to be
created. `vercel redeploy` is the wrong tool (live-v3) - it rebuilds the deployment's own commit, and no
deployment of e8684cf or 9189af4 exists. Use one of: a push to `main` (this PR's merge is itself one), the
Path B deploy-hook sequence at `docs/runbooks/deploy.md:178-185` (`vercel deploy-hooks create ... --ref main`,
`curl -X POST "<hook url>"`, then remove the hook - the URL is a credential), or a dashboard deployment of
`main`. Confirm with `vercel inspect <url> --logs 2>&1 | grep Cloning` and the `grep -c 'aria-label="Story
sections"'` check, not with the dashboard's "Ready" badge.

**Ignored Build Step.** The owner approved this on 2026-09-11 (PRD, Constraints & Assumptions). Keep the
decision logic in the repository and the dashboard value a one-liner that calls it, following the precedent
of `scripts/check-allowbuilds-drift.mjs`: a Node-builtins-only `.mjs` that exports pure functions for its
tests and runs `main()` only when invoked as the command (`scripts/check-allowbuilds-drift.mjs:1-25` and its
last three lines). `pnpm test:scripts` is `node --test "scripts/**/*.test.mjs"`, so a sibling
`scripts/vercel-ignore-build.test.mjs` is picked up with no wiring. Traps, each of which has bitten someone:

- The exit code is inverted relative to a normal gate: **`0` skips the build, `1` continues it**. Confirm
  against Vercel's current documentation before relying on it, and write the contract into the ADR and the
  script's header comment.
- The step runs with the working directory set to the Root Directory (`apps/web`) and before `pnpm install`,
  so the script may use only Node builtins, and the repository root is reachable only because "Include source
  files outside of the Root Directory in the Build Step" is on (the first Troubleshooting row at
  `docs/runbooks/deploy.md:493` exists because of that setting). Resolve the repo root from
  `git rev-parse --show-toplevel` rather than assuming a `../../` hop.
- `git diff HEAD^ HEAD` - Vercel's own example - inspects only the tip commit, so a multi-commit push whose
  earlier commits touched `apps/web` would be skipped. Prefer `$VERCEL_GIT_PREVIOUS_SHA` as the base, verify
  it exists in the shallow clone (`git cat-file -e <sha>^{commit}`), and **exit 1 (build) whenever the base
  cannot be established**. The script must never skip because it could not see, the same rule
  `scripts/check-allowbuilds-drift.mjs` states in its header.
- The build-input set is the whole of what the site is built from: `apps/web/`, `packages/`, `package.json`,
  `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `turbo.json`, `.npmrc` and `.nvmrc`. Everything else - `docs/`,
  `.claude/`, `README.md`, `.github/` - is skippable. Write the list once, in the script, and let the ADR
  point at it rather than restating it.
- Skipping a **production** build means production's SHA no longer equals `main`'s HEAD, which is exactly
  what FR-1 and the epic's success criterion measure. That is why AC 9 exists. Whether production docs-only
  merges skip, or only previews do, is the one part of the policy that needs the owner's go-ahead at
  execution time; skipping only previews already removes 81 of the 100 deployments that caused the outage,
  while skipping production merges as well is what the owner's 2026-09-11 note approved.
- Before relying on skips, confirm with the owner that the `Vercel` context is not a required status check on
  `main`: a skipped build reports as cancelled, and a required check that never arrives would block every
  docs-only merge.

**Runbook edits.** Five separate places, all in `docs/runbooks/deploy.md`, and this file is the one conflict
with #51 (epic, Conflicts to respect), so land the whole runbook change in a single commit and rebase
rather than interleaving: the Prerequisites table (line 32, the Domain control row: expiry and auto-renew),
the mail-records caution (lines 294-300: DMARC beside MX and SPF), the Verify checklist (lines 374-375 and
381-382: the deleted case-study not-found page), Routine deployments (lines 456-458: what `vercel redeploy`
actually does), the Troubleshooting table (line 504 replaced, plus a new rate-limit row) and Not covered
(line 536: analytics). The runbook is followed under pressure, so prefer a command the reader can paste over
prose.

**ADR hygiene.** One new ADR for the skip policy, numbered at PR time (PRD, Constraints & Assumptions:
parallel sessions have collided on numbers). ADR 0005's `## Decision` says "No `vercel.json` is added" and an
accepted Decision is never edited (ADR 0012), which is the reason to use the project setting rather than
adding `apps/web/vercel.json`; if the implementing agent concludes a `vercel.json` is unavoidable, that ADR
has to be superseded by number, not amended. No correction to 0005 is needed for anything in this task as
written.

**Analytics (critic-2).** Two coherent end states. Switching the toggle off is the smaller change: no code,
no new third-party script, and no coupling to #48's Content-Security-Policy. Wiring `<Analytics />` into
`apps/web/src/app/layout.tsx` (the provider tree is at lines 98-110) means #48's CSP must allow
`/_vercel/insights/`, the first-load JS budget in the PRD's Non-Functional Requirements has to be re-measured,
and the console-clean gate will not see the script at all, because it runs against a local `next start`. Both
are Vercel settings or app code, so propose the choice and take the owner's go-ahead. Record whichever is
chosen in the runbook's "No covered / No analytics" bullet.

**Out of this task.** `CLAUDE.md:299` ("Merging to `main` deploys; there is no manual step") becomes
misleading once builds can be skipped deliberately; `CLAUDE.md` belongs to #51 (epic, Conflicts to
respect), so hand #51 the exact wording rather than editing it here. A post-merge or scheduled check that
compares the production deployment SHA with `main` would have caught this in an hour instead of a day; it
adds a workflow file and is not in this task's scope - raise it with the owner, and if approved it belongs
with #50's CI work or as its own follow-up.

  Build Step alone would therefore have left the 2026-09-10 quota exactly where it was. Dependabot is
  now handled by `git.deploymentEnabled` for `dependabot/**`, which stops the deployment being created

  - The exit-code polarity is now tested end to end. Six cases in
    `scripts/vercel-ignore-build.test.mjs` run the script as a process against a throwaway git
    repository, from its `apps/web`, and assert the literal statuses `0` and `1`; the contract test
    asserts `BUILD_EXIT_CODE` too. Mutation-checked: swapping the ternary in `main()` fails 6 cases,
    swapping the two constants fails 7.
  - Writing those tests found a real defect in the direction this gate must never fail in. The
    entry-point guard compared `process.argv[1]` with `import.meta.url` as strings, and Node resolves
    symlinks in the second but not the first, so invoked through any symlinked path `main()` never ran
    and the process exited `0`: Vercel would have cancelled every build, production included, with an
    empty log. Reproduced (`VERCEL_ENV=production node <symlinked path>` printed nothing, exit 0),
    fixed by comparing realpaths, and pinned by a symlink case that fails against the old guard.
    `main()` also sets `process.exitCode` instead of calling `process.exit()`, so the verdict line is
    flushed to a pipe before exit. `scripts/check-allowbuilds-drift.mjs` has the same string guard
    (a gate that silently would not run); it is outside this task and left alone.
  - The docs-only skip cannot fire on a branch's first push, because `VERCEL_GIT_PREVIOUS_SHA` is the
    SHA of the branch's last successful deployment. Confirmed on this branch's own preview build log:
    `Running "node ../../scripts/vercel-ignore-build.mjs"` then
    `BUILD: cannot tell what changed (VERCEL_GIT_PREVIOUS_SHA is not set); building.` ADR 0016's
    Decision and Positive bullet, a new Trade-offs bullet, the runbook table and bullet, and README.md
    now say so.

    branch cut before the merge (Dependabot's #9 and #10) keeps deploying until rebased.
