# Task: Hero story: accessibility, motion and simplification

## Description

The animated story on the home page is the most visible part of the site and the part the gates see
least of. Its text is drawn in alpha-dimmed, hard-coded violet and a transparent-fill gradient that
miss WCAG AA in the light theme, and the accessibility gate passes them because axe can only return
the translucent island as "needs review" rather than as a violation. Three of the story's headings
are announced letter by letter, because every animated heading is rendered one character per span
with no accessible alternative. Hover effects still scatter, flip and drag letters for visitors who
asked the operating system for reduced motion, and seven endless animations keep the main thread
recalculating style every frame long after they have left the screen, against ADR 0009 rule 4. The
Loop phase, the one with the most timer-driven state, has no unit test and replays into a
self-contradicting state when motion is allowed again. Around it sit smaller defects with the same
root: about a fifth of the subsystem never renders (including a boot loader no visitor ever sees,
which survives only as the end-to-end hydration marker), the served HTML ships two headlines, both
toasts and the whole code sample transparent, and `animated-text.tsx` repeats one split-and-cleanup
scaffold fourteen times, so each of the fixes above would otherwise have to be made six to fourteen
times. This task removes those failure modes without redesigning the story.

Branch: fix/hero-a11y-and-motion. Lands as 3 PRs, squash-merged.

### Architecture Patterns

- N/A — no architecture document for this epic. Standing decisions that apply:
  - ADR 0006 "Hydration-safe client state" — `useSyncExternalStore`, a server snapshot of `false`, no `setState` in an effect; both hooks this task leans on follow it.
  - ADR 0009 "Animation performance rules for the home page" (Accepted, corrected 2026-09-10) — rule 2 (a repeating animation moves only `transform` and `opacity`) and rule 4 (an endless animation stops while nothing can see it), plus the server-rendering rationale at `:143`.
  - ADR 0010 "Status colour tokens" — status colours come from `--status-ok`, `--status-warn` and `--status-err`, never a palette class, and status text is never dimmed.
  - ADR 0011 "Colour roles, corrected for scoped surfaces and stacked tints" (superseding ADR 0008) — `--accent` paints surfaces, `--accent-text` is the only accent allowed as text, and a token only passes on the surface it was measured against.
  - ADR 0012 "Correcting factual errors in accepted records" — the procedure if a Consequences statement in an accepted record becomes untrue; an accepted `## Decision` is never edited.
  - ADR 0014 "Playwright starts the server it tests, on a port of its own" — the e2e runs here own their port.
  - From the epic's Architecture Decisions: only the theme tokens from ADRs 0010 and 0011, with no new palette classes and no alpha on text; RED-first acceptance tests that name their fixing issue, with gate specs keeping `retries: 0`; and small squash-merged PRs from a typed branch, with no epic branch.
