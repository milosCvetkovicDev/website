# Task: Production verification of the remediation

## Description

The audit's most urgent finding was that merged work had stopped reaching production: CI was green while
https://miloscvetkovic.dev served a commit two merges behind main, and nothing said so. Every other task in this
epic can end the same way — green in CI and absent, or different, on the real host — because CI tests `next start`
on localhost and never meets Vercel's deployment queue, the headers and cache the CDN actually serves, the public
`*.vercel.app` alias, a link unfurler, or WebKit on a real phone. This task closes that gap for the epic as a
whole. It proves each outcome of #43, #44, #45, #46, #47, #48, #49, #50, #51 on production with commands whose expected output is written down
in advance, adds the two checks no tool can make (the menu on a real phone and a link-preview card), watches the
production logs for 15 minutes after the last deploy, and ends with the owner's sign-off before the epic is
closed. It changes no code: a check that fails becomes a new issue, or reopens the task that owns the outcome,
and is never fixed from inside this task.

Branch: n/a (verification only). Lands as 0 PRs: nothing is committed, and every command and its real output go
on this task's issue.

**Deployment identity (AC 2-4).** `vercel inspect https://miloscvetkovic.dev --logs` resolves the apex alias to
the deployment serving it, and the build log's `Cloning … (Branch: main, Commit: <sha>)` line names the commit
(`docs/runbooks/deploy.md:448-450`). Once #44's Ignored Build Step is live, a docs-only merge produces no
production deployment, so straight after such a merge "equals main HEAD" is the wrong test; the right one is AC
2's path diff against the path list in #44's ADR. `vercel redeploy` is not a recovery: in CLI 59.13.1 it
rebuilds the deployment it is given, with no git ref, so it cannot bring a lagging production up to main
(live-v3, `docs/runbooks/deploy.md:456`). The per-commit script prints the Vercel status beside every commit, so
a build skipped by policy is told apart from one the platform refused whether or not Vercel recorded a
deployment. Run on 2026-09-11 it printed `9189af4 2026-09-10T16:01:26Z none | Deployment rate limited — retry in
24 hours.`, and the same for e8684cf, which is exactly the failure it exists to catch:

```bash
# Start of the window: the merge time of #44's PR.
since="$(gh pr list --state merged --head ci/vercel-ignored-build-step --json mergedAt --jq 'map(.mergedAt) | min')"
gh api --paginate "repos/{owner}/{repo}/commits?sha=main&since=$since" --jq '.[] | "\(.sha) \(.commit.committer.date)"' |
  while read -r sha committed; do
    vercel="$(gh api "repos/{owner}/{repo}/commits/$sha/status" --jq '.statuses[] | select(.context=="Vercel") | .description')"
    dep="$(gh api "repos/{owner}/{repo}/deployments?environment=Production&sha=$sha" --jq '.[0] | select(.) | "\(.id) \(.created_at)"')"
    if [ -n "$dep" ]; then
      state="$(gh api "repos/{owner}/{repo}/deployments/${dep%% *}/statuses" --jq '.[0].state')"
      echo "${sha:0:7} $committed deployed ${dep#* } $state | $vercel"
    else
      echo "${sha:0:7} $committed none | $vercel"
    fi
  done
```

**First-load JavaScript (AC 26).** The sum of the `gzip -9` sizes of the unique `/_next/static/**/*.js` files the

```bash
for r in "${routes[@]}"; do
  total=0
  for js in $(curl -sS "https://miloscvetkovic.dev$r" | grep -oE '/_next/static/[^"]+\.js' | sort -u); do
    total=$(( total + $(curl -sS "https://miloscvetkovic.dev$js" | gzip -9 -c | wc -c) ))
  done
  echo "$r $(( total / 1024 )) KiB"
done
```
