# Task: Head and crawl surface: metadata, social image, canonical, robots, sitemap, icons and security headers

## Description

The site is live, and the surface a recruiter or a crawler meets first is the one nothing measures. No route
serves a preview image, although every route asks X for a large card, so every shared link unfurls as bare
text. Five sub-pages hand X the home page's title and description, and every child route loses og:url,
og:site_name, og:locale and og:type, because Next replaces a nested metadata object rather than merging it.

No page names a canonical URL, while a byte-identical, indexable copy of the whole site answers on the public
`vercel.app` production alias. `robots.txt` disallows `/_next/`, which is where every stylesheet, script and
font lives, so Googlebot renders the pages without them, and it also disallows an `/api/` that does not exist.
The sitemap stamps the build time on all nine URLs and advertises the Coming Soon `/blog` as changing weekly.
The 404 pages emit a `noindex` next to an `index, follow` under the home page's title. The favicon is still
create-next-app's Vercel mark, and nothing declares a theme-color, a color-scheme, a touch icon or a manifest.

Two hardening defects ride along: only Vercel's default HSTS header is sent, and JSON-LD is serialised with a
bare `JSON.stringify` that would let a `</script>` in any value escape the script tag. Every route has to stay
statically prerendered through all of it.

Branch: fix/metadata-and-headers. Lands as 3 PRs, squash-merged.
