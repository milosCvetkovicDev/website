# Task: Documentation accuracy and repository hygiene

## Description

A CV PDF with personal contact details is tracked under `docs/` in a public repository, although the
site deliberately withholds those details and nothing on the site links to it. The design document
that references it also maps each public case-study name to the internal project name it stands for,
which is the same leak in a second place. Separately, the written record has drifted away from the
repository it describes: four accepted ADRs each state something that was untrue on the day they were
accepted, the ADR index disagrees with four records, and the README, `CLAUDE.md`, the deploy runbook
and the pull-request checklist each list the CI gates without the two that #27 added. The README also
claims a shell-command guard that does not exist, names the wrong Vitest major, and omits the
directory that holds a CI gate; the husky hooks point at a README section that has never existed; and
two Shipped plans carry unticked boxes for work that was done. Branch protection on `main` is on,
with required checks bound to the two CI job display names, and no document in the repository says so,
so renaming a job would silently block every pull request. These files are what a reader or an agent
loads before changing code, so each false line hands over a wrong model of the repository. Finally
the clone itself has accumulated 13 squash-merged local branches, 19 orphaned pull-request refs, one
re-created remote branch and two idle worktrees, and the repository's homepage and licence metadata
disagree with the site and with the packages.

Branch: docs/audit-corrections. Lands as 3 PRs, squash-merged.
