# Task: Record the policy, including what is deliberately not built

## Description

A machine reading this repository today cannot learn what the site's posture towards AI crawlers is, or
why. `apps/web/src/app/robots.ts:10` disallows `/_next/` and an `/api/` that does not exist, with no
record of whether either was a decision; nothing says whether training crawlers are welcome; and nothing
says why the site carries no `llms-full.txt`, no FAQPage markup and no `/.well-known/ai-plugin.json` — so
each absence reads as an oversight that the next well-meaning article will offer to fix. This task writes
the record: one ADR carrying the crawler policy with its trade-off stated, a per-measure table saying who
consumes each thing this epic ships and how strong the evidence behind it is, and a dated
"deliberately not built" table covering eighteen mechanisms with the source that kills each one. It then
brings `CLAUDE.md` and `README.md` back in line with a repository that now has route handlers, adds the
`docs/plans/README.md` index row for this epic, and leaves behind one test so the refusal list cannot rot
in silence. It is worth doing because it is the output most likely to still be useful in a year: the
measures in this epic will age, and the pressure to add fashionable files will not stop.

Branch: docs/ai-discoverability-policy. Lands as 2 PRs, squash-merged.

## Measures

### The AI discoverability policy ADR

- **What:** a new record, `docs/adr/NNNN-ai-discoverability-policy.md` (number taken at PR time), using
  the heading set every record in that directory uses (`## Status`, `## Date`, `## Context`,
  `## Decision`, `## Consequences` with `### Positive` and `### Trade-offs`, `## Alternatives
considered`). Its `## Decision` has three parts. **(1) Crawler policy:** one `*` group, `Allow: /`, a
  `Sitemap:` line, nothing else — no training opt-out, no per-bot `Allow` groups, no `Content-Signal`
  line, no allowlist — with the trade-off written in the same breath: every mechanism that earns a
  citation is the mechanism that feeds training, no vendor documents a token meaning "cite me but never
  train on me" that anyone honours, and Cloudflare measured the exchange rate as crawl-to-refer ratios of
  38,065:1 (Anthropic), 1,091:1 (OpenAI), 195:1 (Perplexity), 40.7:1 (Microsoft) and 5.4:1 (Google), with
  roughly 80% of AI bot activity being training, 17% search and 3.2% user actions. The owner accepts that
  because this site is marketing, not a content business, and the record says the choice is revocable.
  **(2) What each shipped measure is for**, one row per measure, each naming its consumer and one of four
  evidence labels — measured, vendor-documented, convention-only, speculative — and, where the honest
  reason is that it demonstrates the owner's engineering, saying exactly that. **(3) The dated refusal
  table**, mechanism / why not / source / date, covering `llms-full.txt`, FAQPage, HowTo, `speakable`,
  `SearchAction`, `ai.txt`, TDMRep, Content-Signals, `/.well-known/ai-plugin.json`, `agents.json`, JSON
  Resume, WebMCP, `/.well-known/agent-skills/index.json`, IndexNow, a self-created Wikidata item, a
  robots.txt allowlist, a nonce-based CSP and an `AGENTS.md` served at the web root. A closing section
  names what would reverse any of it: a documented consumer, which is the thing none of them has.
- **Consumed by:** the owner, the next maintainer, and every future Claude Code session in this
  repository. Nothing outside the repository reads it, and it changes nothing any engine sees.
- **Evidence:** convention-only as a discoverability measure — an ADR is a repository artefact. The claims
  _inside_ it carry their own labels, and every refusal row carries a primary source with a date; the
  strongest are Google's own "You don't need to create new machine readable files, AI text files, markup,
  or Markdown to appear in Google Search" (`developers.google.com/search/docs/fundamentals/ai-optimization-guide`,
  updated 2026-07-10) and Ahrefs' log study of 137,210 domains (2026-06-15), which found 97% of valid
  `llms.txt` files fetched zero times in May 2026.
- **Done when:** the record is `Accepted`, has a row in `docs/adr/README.md`, every refusal row carries a
  URL and an ISO date, and no sentence in it claims a benefit the cited source does not support.

## Technical Details

**The record and where it sits.** `docs/adr/README.md:27-43` lists 0001 to 0015, so the next free number
is at least 0016 — but #57, #59 and #62 of this epic and #44, #45, #48, #50 and #51 of epic #42 each
add a record too, so the number is taken at PR time after checking open branches, exactly as
`docs/adr/README.md:54-57` instructs. The heading set, the `Proposed` → `Accepted` transition and the
`pnpm format` step come from `docs/adr/README.md:58-79`. Accepting the policy before every measure has
shipped is correct rather than premature: `docs/adr/README.md:45-47` states that "`Accepted` means the
decision stands, not that it is implemented", with ADR 0005 (hosting) as the precedent — accepted
2026-09-08, carried out 2026-09-09. If the epic later diverges, the record is corrected under ADR 0012's
rules or superseded by a new number; its `## Decision` is never edited.

**The three shapes the `## Decision` needs, checked against the current code.**

1. _Crawler policy._ `apps/web/src/app/robots.ts:10` is `disallow: ['/api/', '/_next/']` today, which is
   the defect #48 removes — its AC 7 requires `grep -c Disallow` on the served file to print 0. So this
   record describes and justifies the file #48 ships; it does not edit `robots.ts`. Three facts belong in
   it. Blocking a _search_ crawler verifiably costs that vendor's citations, because OpenAI says so:
   sites opted out of OAI-SearchBot "will not be shown in ChatGPT search answers"
   (`developers.openai.com/api/docs/bots`, fetched 2026-09-12). Blocking a _training_ crawler is
   documented as costless for search and citations by Google (Google-Extended "does not impact a site's
   inclusion in Google Search", `developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers`,
   2026-07-14), Apple (`support.apple.com/en-us/119829`, 2026-09-04) and DuckDuckGo — while the one
   measurement that exists points the other way and cannot prove why (cloro, 2026-07-06, 1,058 domains:
   a median 0.003 ChatGPT citations per Google ranking for GPTBot-blockers against 0.417 for non-blockers,
   with the authors' own "The data can't prove causation"). And robots.txt is advice: OpenAI's
   ChatGPT-User ("robots.txt rules may not apply"), Perplexity-User ("generally ignores robots.txt
   rules"), `meta-externalfetcher` and Google's user-triggered fetchers are all documented as exempt,
   Anthropic is the lone outlier claiming blanket compliance for all three of its bots
   (`support.claude.com` article 8896518, 2026-04-07), and TollBit's H1-2026 data puts AI-fetcher
   non-compliance at roughly 15% of European sites carrying disallow rules. Two traps worth a sentence
   each: the legacy tokens `anthropic-ai` and `Claude-Web` appear in countless files, including
   `cloudflare.com/robots.txt`, and in no current Anthropic documentation, so do not add them; and RFC
   9309 (September 2022) makes a specific `User-agent` group override `*` entirely, so a per-bot
   `Allow: /` group would silently exempt that bot from any future `Disallow` — which is the concrete
   reason the policy is one `*` group and nothing else. `Crawl-delay` and `Host:` are not in RFC 9309
   either; `MetadataRoute.Robots` still exposes `host`, and emitting it adds a line no crawler reads.
2. _Per-measure evidence._ One row per measure, consumer plus label. Dates and `TechArticle` (#56,
   #57): vendor-documented — `Article` is one of the 31 live features in Google's gallery (verified
   2026-06-15) and Microsoft states freshness helps AI systems reference the current version
   (`blogs.bing.com`, 2026-02-10); that dates drive AI citation specifically is convention-only and must
   not be asserted. `BreadcrumbList` and `ProfilePage` (#57): vendor-documented for the mechanism
   (`developers.google.com/search/docs/appearance/structured-data/profile-page`, 2026-09-08) and
   speculative as a citation lever — Ahrefs' matched difference-in-differences over 1,885 pages against
   ~4,000 controls (2026-05-11) found AI Overviews −4.6%, AI Mode +2.2%, ChatGPT +2.2%. No knowledge
   panel is promised: the gallery has no `Person` feature at all, and the 90-day `dateModified` rule that
   SEO posts assert appears nowhere in Google's documentation. Metric scope (#56, #58): measured but
   academic — the KDD 2024 GEO paper (`arxiv.org/abs/2311.09735`) reports statistics +37% and cited
   sources +30% relative visibility in generative engines; direction supported, magnitude unknown.
   Headings and real tables (#58): vendor-documented (Google on headings; Microsoft names tables,
   2026-02-10), magnitude unmeasured — and multiple `H1`s were never the problem, the site already has
   exactly one per route. Markdown twins (#59): measured consumption, measured non-consumption by answer
   engines, plus extraction insurance. `llms.txt` (#60): measured non-consumption (Ahrefs, 137,210
   domains, 2026-06-15 — 97% fetched zero times, 77% of the fetches that happened from SEO tooling, 1.1%
   from AI retrieval bots) against vendor-documented publish-side adoption; it ships for completeness and
   coding agents, and the row says so. JSON representation (#60): de-facto standard, best
   effort-to-reach ratio in the epic, because any agent with a fetch tool can read it. Atom feed (#61):
   formal standard with documented consumers, zero evidence of citation effect. MCP server (#62):
   formal-standard protocol, speculative reach, demonstration as the stated reason — nothing discovers an
   MCP server automatically (SEP-2127 server cards were an open pull request on 2026-09-11) and
   Anthropic's Connectors Directory submission portal needs a Team or Enterprise organisation. The gates
   (#55): measured in this repository — Lighthouse 13.4.1 scored `agentic-browsing` 1.0 with four of six
   audits `notApplicable` and SEO 1.0 while every route lacked a canonical.
3. _The refusal table._ One row each, with the source that kills it: `llms-full.txt` — absent from
   `llmstxt.org` and the AnswerDotAI repository, and the published ones have scaled past any context
   window (Cloudflare's 50.8 MB, Anthropic's 34.3 MB, measured 2026-09-12) while this site's whole content
   source is roughly 12 KB, so `/llms.txt` is already complete; Mintlify replaced its own monolith with a
   hierarchy (2026-09-01). FAQPage — the rich result stopped appearing 2026-05-07 and Google deleted the
   documentation page 2026-06-15. HowTo — documentation removed 2023-09-14, never returned, absent from the
   gallery. `speakable` — still BETA after roughly seven years, restricted to US-English Google Home users
   and topical news queries (2026-09-08). `SearchAction` — the sitelinks search box was deprecated
   2024-10-21 and retired globally 2024-11-21. `ai.txt` — a 2023 Spawning proposal; its IETF incarnation
   `draft-car-ai-txt-wellknown` is an unadopted individual submission. TDMRep — a W3C Community Group
   Final Report (2024-02-02), explicitly not a Standard, whose only cited adopter is the spawning.ai API.
   Content-Signals — John Mueller, 2026-07-06: "none of the crawlers / llms use the content-signal
   robots.txt directives", "It was made up by a CDN"; `draft-romm-aipref-contentsignals-00` expired
   unadopted 2026-04-04; its real function is an EU DSM Article 4 rights reservation, not access control —
   and Next 16.3.0's per-rule `other` field makes it a one-line change, so the refusal is about consumers,
   not cost. `ai-plugin.json` — new plugin conversations were blocked 2024-03-19 and all plugin chats shut
   down 2024-04-09; OpenAI's 2026 plugin docs never mention it, and the only well-known path OpenAI fetches
   is `/.well-known/openai-apps-challenge`, a one-time domain proof during directory submission.
   `agents.json` — still 0.1.0 with no evidence of consumption, and a portfolio's model is list-then-read,
   which `tools/list` already covers. JSON Resume — no documented consumer among Google, Bing, ChatGPT,
   Claude or Perplexity, and #60's JSON covers the same content for a wider audience.
   WebMCP — a non-Standards-Track Community Group draft (2026-09-10) in a Chrome origin trial, renamed
   twice in about four months (`window.agent`, `navigator.modelContext`, now `document.modelContext`), with
   no mainstream agent consuming it; it would also light three Lighthouse audits that are currently
   `notApplicable`, which looks like progress on a score that means nothing. `agent-skills` discovery —
   publish-side adoption is real (Cloudflare, Stripe, X, every Mintlify site, verified 2026-09-12) but
   Anthropic closed the Claude Code auto-discovery request (issue 61513) as not planned, `vercel-labs/skills`
   issue 985 reports `index.json` not being fetched, and real consumption is a human typing
   `npx skills add <url>`. IndexNow — the participant registry lists exactly seven endpoints (bing,
   yandex, seznam, naver, yep, internetarchive, amazonbot; fetched 2026-09-12), none of them an AI vendor.
   Wikidata — a self-created item for a non-notable person is deleted and the attempt is visible, and no
   Google documentation describes markup or Wikidata as a route into the Knowledge Graph; this is the one
   row the guard cannot check, because it is an off-site action, and the row says so. Allowlist — honoured
   only by the compliant crawlers that were never the worry, guaranteeing exclusion of any operator
   forgotten, with the enforcing half living in Vercel Firewall dashboard state that no review sees.
   Nonce CSP — Next documents that it disables static optimization and ISR and is incompatible with PPR
   (`nextjs.org/docs/app/guides/content-security-policy`, 16.3.5, lastUpdated 2026-03-20), so it would turn
   all nine routes into request-time renders; #48 keeps security headers in the `headers()` form.
   Web-root `AGENTS.md` — a repository convention with no HTTP story, and imperative text by design, which
   is the shape of a prompt-injection surface; the useful `AGENTS.md` is a git-tracked one at the repo root,
   which is repo hygiene and not in this epic.

**The Next.js 16 specifics, with the traps named.** Route handlers are **not** static by default: a `GET`
with no `dynamic` export becomes a serverless function, changed in v15.0.0-RC and confirmed by build probe
on next 16.3.4 (2026-09-12) — `○ /llms.txt` with `export const dynamic = 'force-static'`, `ƒ /llms-full.txt`
without it, with no `.body`/`.meta` file emitted. That one line is the whole difference, which is why the
ADR records it as a rule and #55's build-output gate enforces it. `force-static` is removed **only
when `cacheComponents` is enabled**: it is absent from the main route-segment-config options table, which
reads like removal, and fully documented in the "Caching and Revalidating (Previous Model)" guide
(lastUpdated 2026-08-25). This repository does not set `cacheComponents`, so it is the correct mechanism
today — and adopting Cache Components later would break every handler that relies on it, which the record
names as the one change that forces a revisit. `[slug].md` cannot work: Next types a partial dynamic
segment as a literal with zero params (`RouteHandlerConfig<"/work/[slug].md">` with `params: Promise<{}>`,
failing typecheck with TS2344), which is why the twins are `/work/<slug>/index.md` and why §Gotchas gets a
line so nobody retries it. Two more that belong in the record only as pointers, not decisions:
`sitemap.ts` is prerendered, so `lastModified: new Date()` freezes at build time (#48 removes the stamp,
#56 restores it from real data), and Vercel's CDN already includes `Accept` in its cache key, so the
uniform `/index.md` shape needs no `Vary` gymnastics — which is part of why it was chosen over content
negotiation.

**One measured nuance the record must not overstate.** The extraction argument for the twins is about
_shape_, not missing content. A GPTBot-user-agent fetch of the live home page on 2026-09-12 returned 200
with the whole story in the prerendered HTML (about 5,156 characters of body text against 5,320 rendered),
because ADR 0009's decision to import the phases directly means they prerender. Chrome's `innerText` and a
tag-strip that joins with nothing both reassemble "Most bugs live in the gap between what you asked for and
what you meant" correctly; the `M o s t  b u g s` variant appears only under an extractor that inserts
whitespace at tag boundaries. So the honest sentence is that the 681 per-character spans are a hazard for
some extractors and a Markdown twin is insurance against that — not that the site is invisible. Likewise
the no-JavaScript premise rests on one primary measurement (Vercel/MERJ, ~1.3bn fetches, 2024-12-17); no
vendor has documented rendering since, so the record dates it and calls it 21 months stale rather than
current fact.

**What this task consumes from epic #42, rather than reimplementing.** #48 owns `robots.txt` hygiene
(including the `/_next/` removal), canonical URLs, the `mergeMetadata` and `serializeJsonLd` helpers,

`noindex` — the crawler-policy section cites that work as its premise and adds no rule of its own to any of
those files. #43 owns `apps/web/e2e/routes.ts` and the served-HTML test pattern, which is what
`CLAUDE.md` §Quality gates names when it lists the no-JavaScript floors; this task writes no spec. #47 owns
the per-character span fix, so the extraction paragraph above is dated to its measurement and does not
assert the spans are still present after #47 lands. #49 owns the metric contradictions, so the honesty
claims about metrics belong to #56 and #49, and the record only labels the evidence.
